`@spooky-sync/client-svelte` connects Svelte 5 apps to Sp00ky, built on runes. A live query is an
object of reactive getters (`posts.data`, `posts.isLoading`) that markup, `$derived` and `$effect`
track like any other state. Every write lands in the local database first, and the engine syncs it
with the server and every other tab and device in the background. Reloads paint from the local
cache, and the app keeps working offline.

This guide builds a complete app: setup, queries, sign-in, writes, sync status, files,
collaborative fields and peer to peer channels. It needs Svelte 5.29 or newer.

<Warning title="Browser only">
  The client runs SurrealDB and SQLite as WebAssembly with IndexedDB / OPFS storage and web
  workers, so it only runs in the browser. `<Sp00kyProvider>` renders its `fallback` during a
  server render; in SvelteKit, turn server rendering off as shown below.
</Warning>

## Queries

`useQuery(query, options?)` subscribes a component to a live query. It takes a getter that builds
the query: the getter re-runs when the state it reads changes, and the query is re-registered only
when its identity (its SurrealQL and vars) changes, not on every rebuild.

<CodeBlock fileName="src/lib/PostList.svelte" code={queryCode} lang="svelte" />

Return `null` from the getter (or pass `{ enabled: () => false }`) to skip a query until its inputs
exist:

<CodeBlock code={dependentCode} lang="svelte" />

A query that never changes can be passed as is (`useQuery(db.query('tag').build())`), and
`useQuery(db, query, options?)` takes the client explicitly, for code outside a provider. The query
builder itself (`where`, `related`, `orderBy`, `limit`, `one`) is covered in
[Reactive queries](/docs/client/queries).

<Warning title="Do not destructure a result">
  Every field is a getter. `const { data } = useQuery(...)` copies `data` once and never updates.
  Keep the object and read fields where you need them, in markup or in `$derived`:

  <CodeBlock code={destructureCode} lang="typescript" />
</Warning>

### Result

Every field of the result is a reactive getter:

| Field | Meaning |
|---|---|
| `data` | Rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared between updates. |
| `error` | Registration or sync error (e.g. SSP 503 during bootstrap). Never thrown; the sync scheduler retries underneath. |
| `isLoading` | Cold first load only: nothing painted for this query, the server has not answered, and registration has not failed. A paint from the local cache ends it; the server answering with zero rows ends it too. |
| `isFetching` | The sync engine is pulling records for this query (registration, a sync round). |
| `isAuthoritative` | `data` holds the rendered rows of a known membership: the server's answer, or the one a previous session left on this device. From here `data` is an answer, not a cache guess. |
| `hasData` | `data` holds something: rows for a list, a row for `.one()`. |
| `isEmpty` | Authoritative **and** no data: the server said "no rows". Render empty states on this, never on a bare `!hasData`. |
| `isSettled` | Authoritative **and** idle. The gate for trusting a short window as the end of a list, and for "create it if it is missing". Not monotonic: a later sync round re-enters `isFetching`. |

When the query's identity changes, the previous `data` stays on screen until the new query
answers, while the flags reset. Growing a `.limit()` therefore never flashes an empty list:

<CodeBlock code={loadMoreCode} lang="svelte" />

Options: `{ enabled?: boolean | (() => boolean), deregisterOnCleanup?: boolean }`. Use
`deregisterOnCleanup` for viewport windows that mount and unmount a query per page, see
[Pagination](/docs/client/pagination).

## Sync status

`useSyncStatus` reports the connection, `usePendingMutations` the number of writes not yet on the
server. Together they make the usual offline banner:

<CodeBlock fileName="src/lib/ConnectionBanner.svelte" code={statusCode} lang="svelte" />

| Hook | Returns |
|---|---|
| `useSyncStatus()` | `status`, `isHealthy`, `isDegraded`, `isOffline`, `isReconnecting`, `everConnected`, `connection`, `health` |
| `usePendingMutations()` | `.current`: the number of local writes waiting to sync |
| `useSyncActivity(options?)` | `isDownloading`, `isUploading`, `fetchingQueries`, `pendingMutations`, debounced for a traffic indicator |
| `useStorageStatus()` | `status`, `isPersistent`, `isMemoryFallback`, `health` for the local database |

What to show for each state is covered in [Offline & sync health](/docs/client/offline-sync).

`useSyncStatus`, `useStorageStatus` and `usePendingMutations` need no component: they also take
the client as their argument, so one shared instance can live in a `.svelte.ts` module. Hooks that
open something (`useQuery`, `useCrdtField`, `useChannel`, the file hooks) or own timers
(`useSyncActivity`) must run while a component initialises, or inside `$effect.root`.

## Files and images

[`useFileUpload` and `useDownloadFile`](/docs/client/buckets) upload to and read from a bucket.
`<BucketImage>` renders a bucket file as an image, revealing it only once it is decoded, and
`<Blurhash>` / `useBlurhash` paint a placeholder while it loads. Paths are getters, the components
take `class` / `imgClass`, and the placeholder is a `fallback` snippet. On a path change the
previous object URL stays valid until the next one is ready, so the image never flashes broken.

export const authCode = `import { useDb } from '@spooky-sync/client-svelte';
import type { schema } from './schema.gen';

export function useAuth() {
  const db = useDb<typeof schema>();
  // undefined until the client reports, then a user id or null.
  let userId = $state<string | null | undefined>(undefined);

  // subscribe() answers right away with the current user, then on every
  // sign-in and sign-out. It returns the unsubscribe the effect tears down with.
  $effect(() => db.auth.subscribe((id) => (userId = id)));

  return {
    get userId() {
      return userId;
    },
    get isChecking() {
      return userId === undefined;
    },
    signIn: (username: string, password: string) =>
      db.auth.signIn('account', { username, password }),
    signUp: (username: string, password: string) =>
      db.auth.signUp('account', { username, password }),
    signOut: () => db.signOut(),
  };
}`;

export const crdtCode = `<script lang="ts">
  import { useCrdtField } from '@spooky-sync/client-svelte';

  // id is the full record id, e.g. 'note:abc'; summary is the column's plain text.
  let { id, summary }: { id: string; summary: string } = $props();
  const field = useCrdtField('note', () => id, 'summary');
  let value = $state('');

  // Follow the document: local and remote edits alike update the textarea.
  $effect(() => {
    const doc = field.current?.getDoc();
    if (!doc) return;
    const text = doc.getText('summary');
    value = text.toString();
    return doc.subscribe(() => (value = text.toString()));
  });
</script>

<textarea
  value={field.current ? value : summary}
  readonly={!field.current}
  oninput={(e) => {
    const doc = field.current?.getDoc();
    if (!doc) return;
    doc.getText('summary').update(e.currentTarget.value); // minimal diff
    doc.commit();
  }}
></textarea>`;
