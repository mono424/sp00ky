# `@spooky-sync/client-solid` — agent guide

## What this package is

The SolidJS binding for sp00ky. Exposes a `Sp00kyProvider` that initializes a `Sp00kyClient` and a set of reactive hooks (`useDb`, `useQuery`, `useCrdtField`, `useFileUpload`, `useDownloadFile`). All hooks expect to be called inside a `<Sp00kyProvider>` boundary.

## Setup pattern

```ts
// db.ts
import type { SyncedDbConfig } from '@spooky-sync/client-solid';
import { schema, SURQL_SCHEMA } from './schema.gen'; // generated by `spky generate`

export const dbConfig: SyncedDbConfig<typeof schema> = {
  schema,
  schemaSurql: SURQL_SCHEMA,
  database: {
    namespace: 'main',
    database: 'app',
    endpoint: 'ws://localhost:8666/rpc',
    store: 'memory',           // or 'indexeddb' for persistence
    persistenceClient: 'localstorage',
  },
};
```

```tsx
// App.tsx
<Sp00kyProvider config={dbConfig}>{/* app */}</Sp00kyProvider>
```

Provider props: `config` (read once, when the provider mounts), `fallback`, `preload` (awaited before children render, best-effort), `onReady`, `onError`, `eager`. The client is initialized in `onMount`, so server renders show the fallback. A client that was handed to the tree is deliberately not closed on cleanup; a non-eager one whose init outlived the provider is.

`eager` renders the children at once, on a `SyncedDb` that is not initialized yet (`new SyncedDb(config, { eager: true })`: its core client is created on first use, `db.isReady` / `db.whenReady()` say when `init()` is done; `db.isReady` is a plain getter, not a signal). With `localEngine: 'rows'`, `useQuery` then has, the first time `data()` is read, the rows the query showed the last time the app was open (`db.peekQuery`, the engine's paint cache) with `isLoading()` false and `isSettled()` false, and the query itself, which waits for `init()` like every query and write made early, replaces them when it answers. A query whose identity changes before the client is ready is painted the same way. Everything that reports state (auth, feature flags, sync status) reports its not-known-yet default until the client is ready, so gate what a signed-out visitor must not see on `db.whenReady()`. `fallback` is never rendered and `preload` no longer holds the UI back. Client-rendered trees only: a server render still produces the fallback. Without `eager`, a `SyncedDb` used before `init()` still throws `SyncedDb not initialized`.

## Key hooks

- **`useDb<typeof schema>()`** — returns the `SyncedDb<S>` instance. Methods:
  - `db.create(id, payload)` — `id` is a full record ID like `'thread:abc'`.
  - `db.update(table, id, payload, options?)` — `options.debounced` coalesces updates; with `flushOnHide` (default `true`) a pending patch survives a reload or closed tab.
  - `db.delete(table, idOrSelector)`.
  - `db.query(table)` — returns a `QueryBuilder`. Chain `.related()`, `.orderBy()`, `.limit()`, etc., end with `.build()`.
  - `db.preload(query, options?)` — registers the query without subscribing. Resolved before on this device: returns instantly. Never resolved: awaits the server's membership and every record. Signed out without `enableAnonymousLiveQueries`: returns instantly (no membership is ever sent to that session). `options.signal` aborts a cold wait; `refresh`/`staleTime` are ignored. Evicted a ttl after registration unless a view mounts the same query.
  - `db.run(backend, route, payload)` — call a backend RPC route.
  - `db.bucket(name)` — get a `BucketHandle` for file storage.
  - `db.remoteQuery(sql, vars?)` — one-shot remote read through the client's queued, connect-gated path (skips cache).
  - `db.useRemote(fn)` — escape hatch to the raw `Surreal` client (skips cache AND the connect gate).
  - `db.authenticate(token)`, `db.signOut()`, `db.auth`.
  - `db.pendingMutationCount`, `db.subscribeToPendingMutations(cb)`.
  - `db.isReady`, `db.whenReady()`, `db.peekQuery(query)`: readiness, and the rows to paint from in an `eager` tree (see Setup pattern). `useQuery` peeks on its own.
- **`useQuery(() => db.query(...).build())`** — reactive query. Returns `{ data, status, error, ... }` accessors. The factory function is tracked, so passing reactive params (signals) re-runs the query.
- **`useChannel(query, peers)`** (experimental peer to peer channels): opens a WebRTC channel for the component's lifetime to `peers` (a list or an accessor; own id skipped; both sides must list each other) for the rows `query` matches. `query` is a builder, built query, list, or accessor of one (nothing closes the channel) on a `-- @channel` table; only its `where` counts (evaluated per row, never registered), and the hook is typed from it. Returns `{ status(), peers(), update, create, delete }`; status is `idle` / `connecting` / `connected` / `failed` / `unsupported`. Plain `db.update` / `db.create` / `db.delete` on rows matching an open channel reach its peers in tens of ms and every query showing the row reflects them (a peer's create lands in the cache like an own optimistic create); `-- @ephemeral` fields go ONLY to peers. `orderBy` / `limit` / `offset` / `select` / `.one()` are ignored by a channel and warn unless the query has `.ignoreUnusedArgs()`. `db.channel(query, peers)` outside components. Peer writes are filtered by the client config `channels.accept[table]`. See `/docs/client/channels`.
- **`createPreload(() => db.query(...).build(), options?)`** — reactive, fire-and-forget prewarm (same overloads/`enabled` as `useQuery`, plus `signal`). Registers a query the user is likely to open next (e.g. a list row's detail). For blocking first-load, use the `Sp00kyProvider` `preload` prop instead.
- **`useCrdtField(table, () => recordId, field)`**: opens a `@crdt` field and returns an accessor that is `null` until it is open, then a `CrdtField`. Bind the editor to `field()?.getDoc()` (a `LoroDoc`: `loro-prosemirror` plugins for `@crdt prosemirror`, `doc.getText(field)` for `@crdt text`); edits sync themselves, so there is no `db.update` for them. Reopens when the id changes, closes on cleanup. To give a not-yet-created record content, use `db.getSp00ky().createCrdtDraft(table, field)`, then after `db.create` call `openCrdtField(table, id, field, draft)` and `await closeCrdtField(...)`. Only the record id is an accessor.
- **`useImpersonation()`**: `{ impersonation, isImpersonating, stop }` for admin impersonation started from the DevTools (`impersonation.enabled` in sp00ky.yml). The client already renders its own warning bar with a Stop button; use the hook only for extras, such as hiding destructive actions while impersonating, or pass `{ rendersBanner: true }` when the app draws its own banner under `impersonationBanner: { mode: 'custom' }`. See `/docs/client/impersonation`.
- **`useFileUpload()`** / **`useDownloadFile()`** — bucket helpers; the upload result includes the storage path you write into a record column. `useDownloadFile` reads through the durable OPFS blob cache (options `{ cache, persist, pin, revalidate }`), so images survive a reload and paint offline; `refetch()` bypasses every layer.

## Re-exports for convenience

- `RecordId`, `Uuid` from `surrealdb`.
- Query-builder types: `TableModel`, `TableNames`, `GetTable`, `QueryResult`, etc. (see `@spooky-sync/query-builder/AGENTS.md`).
- `Model<S, T>`, `GenericModel`, `ModelPayload` — typed row shapes.

## Common gotchas

- **`useDb()` requires `<typeof schema>`.** Without the generic, all calls fall back to `unknown` and you lose type safety.
- **A `@crdt` column is the server-written plain text of its document.** Read it with `useQuery` for previews, search and filters (it trails live edits until the server folds, a few seconds); edit it only through `useCrdtField`. Set it only in the `db.create` that makes the record (its initial text, so lists show it before the first fold); a later `db.update` keeps the old value.
- **Generate IDs explicitly.** `const id = new Uuid().toString()`, then `db.create(\`thread:\${id}\`, ...)`. SurrealDB's auto-id only fires on direct DB writes, not through the sync queue.
- **`useQuery` factories must call `.build()` (or `.all()`, `.first()`, etc.).** A bare `db.query('thread')` is a builder, not a query — `useQuery` will throw or return forever-loading.
- **Provider is mandatory.** Calling any hook outside `<Sp00kyProvider>` throws.
