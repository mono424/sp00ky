`@spooky-sync/client-svelte` is the Svelte 5 binding, built on runes. It wraps the same core client
as the [React](/docs/guide/react) and [Solid](/docs/guide/solid) bindings and exposes the same hooks,
written the Svelte way: a hook returns an object whose fields are reactive getters (`posts.data`,
`posts.isLoading`), and an input that should follow your state is passed as a getter
(`() => db.query(...).build()`). It needs Svelte 5.29 or newer; Svelte 4 is not supported.

<Warning title="Browser only">
  The core client runs SurrealDB and SQLite as WebAssembly, with IndexedDB / OPFS storage and web
  workers. `<Sp00kyProvider>` creates the client in `onMount`, so a server render only produces its
  `fallback`. In SvelteKit, turn server rendering off for the app (`export const ssr = false` in the
  root `+layout.ts`): the core client does not load on the server, and a local-first app paints
  from the local cache anyway.
</Warning>

## What "native" means here

- **Runes, no stores.** Results live in `$state.raw` and are read through getters, so markup,
  `$derived` and `$effect` track exactly the fields they read.
- **Structural sharing.** Each live emission is merged into the previous result: rows are matched
  by `id`, unchanged rows keep their object identity, and a deep-equal emission is the same value.
  A keyed `{#each}` only updates the rows that changed, and nothing reading `data` re-runs for an
  emission that changed nothing. Rows stay plain objects, never deep proxies.
- **Engine status through `createSubscriber`.** `useSyncStatus`, `usePendingMutations` and the other
  status hooks subscribe to the engine only while something reads them, read the engine's own
  current value (nothing to go stale), and unsubscribe when the last reader is gone. The same
  primitive backs Svelte's `MediaQuery`.
- **Lifecycle in effects.** Query registrations, CRDT fields, channels and file leases are opened in
  `$effect` and released in its teardown, so they end with the component.
- **Snippets and attachments.** The provider's `fallback` is a snippet; `<BucketImage>` reveals the
  image through an `{@attach}` decode gate.
- **`$state` payloads are safe to write.** A `$state` object is a Proxy, which cannot reach the
  sqlite and shared-tabs workers. Writes copy plain objects and arrays before they reach the core,
  and leave class instances (`RecordId`, `Date`, bytes) as they are.
- **No optimistic layer.** The engine already commits writes locally and re-renders through live
  queries before it syncs. Mutations are plain `await db.create(...)` calls; `useSubmission` only
  adds button pending and error state.

### Result surface

The flags are the same contract as the [Solid 2](/docs/guide/solid2#result-surface) and
[React](/docs/guide/react#result-surface) bindings, as reactive getters:

| Field | Meaning |
|---|---|
| `data` | Rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared between emissions. |
| `error` | Registration or sync error (e.g. SSP 503 during bootstrap). Never thrown; the sync scheduler retries underneath. |
| `isLoading` | Cold first load only: nothing painted for this identity, the server has not answered, and registration has not failed. A paint from the local cache ends it; the server answering with zero rows ends it too. |
| `isFetching` | The sync engine is pulling records for this query (registration, a sync round). |
| `isAuthoritative` | `data` holds the rendered rows of a known membership: the server's answer, or the one a previous session left on this device. From here `data` is an answer, not a cache guess. |
| `hasData` | `data` holds something: rows for a list, a row for `.one()`. |
| `isEmpty` | Authoritative **and** no data: the server said "no rows". Render empty states on this, never on a bare `!hasData`. |
| `isSettled` | Authoritative **and** idle. The gate for trusting a short window as the end of a list, and for "create it if it is missing". Not monotonic: a later sync round re-enters `isFetching`. |

When the query's identity changes, the previous `data` stays on screen until the new identity
emits, while the flags reset. Growing a `.limit()` therefore never flashes an empty list:

<CodeBlock code={loadMoreCode} lang="svelte" />

Options: `{ enabled?: boolean | (() => boolean), deregisterOnCleanup?: boolean }`. Use
`deregisterOnCleanup` for viewport windows that mount and unmount a query per page, see
[Pagination](/docs/client/pagination).

Engine writes are already optimistic and local-first, so mutations are plain calls. A `$state`

An error there means the local commit failed. Sync failures surface through `useSyncStatus` and
`usePendingMutations` instead. To track a backend job, query its outbox row: `db.run()` writes one
with `status: 'pending'`.

## Status hooks

Same shapes as the other bindings, as getters: `useDb`, `usePendingMutations`,
[`useSyncStatus`](/docs/client/offline-sync), [`useSyncActivity`](/docs/client/offline-sync#traffic-indicator),
[`useStorageStatus`](/docs/client/offline-sync), [`useFeatureFlag`](/docs/client/feature-flags),
`useAppRelease`, [`useImpersonation`](/docs/client/impersonation) and [`useCrdtField`](/docs/client/crdt).
A hook with a single value returns it as `.current`, like `svelte/reactivity` does
(`usePendingMutations().current`, `useCrdtField(...).current`).

<CodeBlock fileName="src/lib/ConnectionBanner.svelte" code={statusCode} lang="svelte" />

`useSyncStatus`, `useStorageStatus` and `usePendingMutations` need no component: they also take
the client as their argument, so one shared instance can live in a `.svelte.ts` module. Hooks that
open something (`useQuery`, `useCrdtField`, `useChannel`, the file hooks) or own timers
(`useSyncActivity`) must run while a component initialises, or inside `$effect.root`.

## Files and images

`<BucketImage>` / `<Blurhash>` components behave as in the other bindings. Paths are getters, the

## Coming from React or Solid

| client-react | client-svelte |
|---|---|
| `useQuery(q)`, `null` to skip | `useQuery(() => q)`, the getter returns `null` to skip |
| `posts.data`, `posts.isLoading` (values per render) | `posts.data`, `posts.isLoading` (getters: never destructure) |
| `{ enabled: boolean }` | `{ enabled: boolean \| (() => boolean) }` |
| `useSubmission(fn)` | `useSubmission(fn)`, no provider needed |
| `usePendingMutations()` returns a number | `usePendingMutations().current` |
| `useCrdtField(table, id, field)` | `useCrdtField(table, () => id, field).current` |
| `useDownloadFile(bucket, path)` | `useDownloadFile(bucket, () => path)` |
| `<BucketImage className="..." fallback={<Plate />}>` | `<BucketImage class="...">` with a `fallback` snippet |
| `ref={image.gate}` plus `src={image.url}` | `{@attach image.gate}` (sets `src`) |
| everything on `useDb()` | unchanged |

From the Solid bindings, accessors become getters: `posts.data()` is `posts.data`, and
`createQuery(() => q)` is `useQuery(() => q)`. There is no `ready()` / suspense mode; branch on
`isLoading` and `isEmpty`.

export const queryCode = `<script lang="ts">
  import { useDb, useQuery } from '@spooky-sync/client-svelte';
  import type { schema } from './schema.gen';

  const db = useDb<typeof schema>();
  const posts = useQuery(() =>
    db.query('post').related('author').orderBy('created_at', 'desc').limit(20).build()
  );
</script>

{#if posts.isLoading}
  <div>Loading…</div>
{:else if posts.isEmpty}
  <div>No posts yet.</div>
{:else}
  <ul>
    {#each posts.data as post (String(post.id))}
      <li>{post.title} by {post.author?.username}</li>
    {/each}
  </ul>
{/if}`;

export const submissionCode = `<script lang="ts">
  import { useDb, useSubmission } from '@spooky-sync/client-svelte';

  const db = useDb<typeof schema>();
  let title = $state('');
  const save = useSubmission((t: string) =>
    db.create('post:' + crypto.randomUUID(), { title: t })
  );
</script>

<form
  onsubmit={(e) => {
    e.preventDefault();
    void save.submit(title);
  }}
>
  <input bind:value={title} />
  <button disabled={save.pending}>Save</button>
  {#if save.error}<p>{save.error.message}</p>{/if}
</form>`;
