# `@spooky-sync/client-angular`: agent guide

## What this package is

The **Angular** binding for sp00ky, built on signals (peer `@angular/core` / `@angular/common` `^21 || ^22`; zoneless and zone.js both work). Same `SyncedDb` and the same function set as `@spooky-sync/client-react` / `client-svelte` / `client-solid2`, written the Angular way:

- `provideSp00ky(config, { preload? })` in the application providers (`app.config.ts`). It provides `SyncedDb` (also the DI token) and starts it in an app initializer, so components render once the client is ready. No wrapper component.
- `inject*` functions return **read-only signals**: `posts.data()`, `posts.isLoading()`. Call them in templates, `computed()` and `effect()`.
- An input that should follow state is a **signal or a function**: `injectQuery(() => this.db.query('post').where({ author: this.authorId() }).build())`, `injectCrdtField('post', this.postId, 'body')` (an `input()` is a signal), `injectDownloadFile('covers', this.path)`. A plain value is fixed.
- A function with a single value returns that signal: `injectPendingMutations()`, `injectCrdtField(...)`.
- Every `inject*` function must run in an **injection context** (field initializer, constructor, factory, `providedIn: 'root'` service) and ends with it via `DestroyRef`. Pass `{ injector }` to call one anywhere else (like Angular's `effect()` / `toSignal()`). `injectSubmission` needs no context.

Browser only. The core client runs SurrealDB / SQLite as WebAssembly in web workers with IndexedDB / OPFS. During a server render `provideSp00ky` never starts the client and the engine-backed `inject*` functions throw ("runs in the browser only"); render such components in `@defer` blocks or on `renderMode: RenderMode.Client` routes.

Internals: `injectQuery` keeps rows in a `signal` and structurally shares each live emission with the previous one (`share` in `src/query.ts`): rows matched by `id` keep their object identity, and a deep-equal emission returns the previous value so the signal does not notify. Registrations, CRDT fields, channels and file leases live in `effect()` and end with the injection context. Status functions subscribe to the engine on creation (no effects, so they work in services) and read the engine's own current value. DOM work (`Blurhash`, `ImageGate`) runs in `afterRenderEffect`, never on the server.

Built with ng-packagr (Angular Package Format, partial compilation); published from `dist/`.

## Setup pattern

```ts
// src/app/db.ts
import type { SyncedDbConfig } from '@spooky-sync/client-angular';
import { schema, SURQL_SCHEMA } from './schema.gen'; // generated by `spky generate`

export const dbConfig: SyncedDbConfig<typeof schema> = {
  schema,
  schemaSurql: SURQL_SCHEMA,
  database: {
    namespace: 'main',
    database: 'app',
    endpoint: 'ws://localhost:8666/rpc',
    store: 'indexeddb',
    // Angular CLI only: the app bundles the engine's worker (see below).
    workers: {
      surreal: () =>
        new Worker(new URL('./sp00ky-surreal.worker', import.meta.url), { type: 'module' }),
    },
  },
};

// src/app/app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [provideZonelessChangeDetection(), provideRouter(routes), provideSp00ky(dbConfig)],
};
```

`config` may be a factory run in the injection context. `preload` is awaited before the first render, best-effort. A failed `init()` fails bootstrap (`bootstrapApplication(...).catch(...)`); put a splash inside `<app-root>` in `index.html`. The client is closed when the app is destroyed. Without `provideSp00ky` (tests, a self-made client): `{ provide: SyncedDb, useValue: db }`.

### Angular CLI build settings (required)

The Angular CLI (`@angular/build:application`) does not bundle a `new Worker(new URL(...))` inside a dependency and does not copy `.wasm` files referenced via `new URL(..., import.meta.url)`. So the app:

1. Installs `@surrealdb/wasm` directly and adds `src/app/sp00ky-surreal.worker.ts` = `import '@surrealdb/wasm/worker';` (and, for `localEngine: 'sqlite'`, `sp00ky-sqlite.worker.ts` = `import '@spooky-sync/core/sqlite-worker';` plus `workers.sqlite`).
2. Sets `"webWorkerTsConfig": "tsconfig.worker.json"` (lib `webworker`, includes `src/**/*.worker.ts`; exclude those from `tsconfig.app.json`).
3. Copies to the output root with `assets`: `@spooky-sync/ssp-wasm/pkg/ssp_wasm_bg.wasm`, `@surrealdb/wasm-native/dist/index_bg.wasm`, `@spooky-sync/core/dist/tabs-broker-worker.js`, `@sqlite.org/sqlite-wasm/dist/{sqlite3.wasm,sqlite3-opfs-async-proxy.js}`. With pnpm, hoist the first, second and fourth package via `public-hoist-pattern[]` in `.npmrc`.
4. Excludes `@spooky-sync/client-angular`, `@spooky-sync/core`, `@spooky-sync/ssp-wasm`, `@surrealdb/wasm`, `@surrealdb/wasm-native`, `@sqlite.org/sqlite-wasm` from the dev server's `prebundle`.
5. Optionally `"allowedCommonJsDependencies": ["pino"]`.

Missing any of these shows as a 404 on `worker-agent.mjs` / a `.wasm` file and an app that never bootstraps (init waits on the worker).

## Key API

- **`provideSp00ky(config, options?)`**: `EnvironmentProviders`. `options.preload?: (db) => Promise<void>`.
- **`injectDb<typeof schema>(options?)`**: the `SyncedDb<S>` (same instance as `inject(SyncedDb)`). `create`, `update`, `delete`, `query`, `preload`, `run`, `channel`, `bucket`, `remoteQuery`, `useRemote`, `auth` / `signOut`, `pendingMutationCount`, `syncHealth` / `storageHealth` and their subscribe methods. Throws a readable error without a provider.
- **`injectQuery(query, options?)`**: live query. `query` is a function (or signal) returning a BUILT query (`.build()`, `.one().build()`) or `null` / `undefined` to skip; a fixed built query can be passed directly. Re-registration keys on the identity hash (surql + vars), not on rebuilds. Result signals:
  - `data`: rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared.
  - `error`: registration / sync failure (e.g. SSP 503 NOT_READY). Never thrown; the scheduler retries.
  - `isLoading`: cold first load only (nothing painted for this identity, server not heard, no error).
  - `isFetching`: a fetch cycle is in flight.
  - `isAuthoritative`: `data` holds the rendered rows of a known membership. Latched until the identity changes.
  - `hasData`: rows for a list, a row for `.one()`.
  - `isEmpty`: authoritative AND no data. Empty states go on this, never on `!hasData()`.
  - `isSettled`: authoritative AND idle. Gate windowed-list end detection and create-if-missing on it. Not monotonic.
  - Options: `enabled?: boolean | Signal<boolean> | (() => boolean)`, `deregisterOnCleanup?: boolean`, `injector?: Injector`.
  - On an identity change the previous `data` stays until the new identity emits (flags reset), so growing `.limit()` never flashes empty.
- **`injectPreload(query, options?)`**: fire-and-forget prewarm of a likely-next query, keyed on its identity. Options: `enabled?`, `signal?`, `injector?`.
- **`injectSubmission(fn)`**: `{ submit, pending, error, result, clearError }`. `submit` never rejects. No injection context needed.
- **`injectPendingMutations(options?)`**: `Signal<number>`.
- **`injectSyncStatus(options?)`**: `{ health, status, isHealthy, isDegraded, everConnected, isOffline, connection, isReconnecting }`.
- **`injectSyncActivity(options?)`**: `{ fetchingQueries, pendingMutations, isDownloading, isUploading }`, debounced on (`downloadDelayMs` 200, `uploadDelayMs` 150, `uploadThreshold` 0), off at once.
- **`injectStorageStatus(options?)`**: `{ health, status, isPersistent, isMemoryFallback }`.
- **`injectImpersonation({ rendersBanner?, injector? })`**: `{ impersonation, isImpersonating, stop }`.
- **`injectFeatureFlag(key, { fallback?, ttl?, injector? })`**: `{ variant, payload, enabled }`. The handle closes with the context.
- **`injectAppRelease({ app, currentVersion, ttl?, injector? })`**: `{ latestVersion, updateAvailable, mandatory, cacheBust, reload }`.
- **`injectCrdtField(table, recordId, field, options?)`**: `Signal<CrdtField | null>`, `null` until loaded. `recordId` is a signal, function or value.
- **`injectChannel(query, peers, options?)`** (experimental): WebRTC channel for the context's lifetime for the rows `query` matches (a builder, built query, or list, on a `-- @channel` table; only its `where` counts; `null` closes it). Both arguments may be signals / functions, compared by value. Returns `{ status, peers, update, create, delete }` (status / peers are signals). See `/docs/client/channels`.
- **Files**: `injectFileUpload(bucket, options?)` (`{ upload, download, remove, exists, isUploading, error, clearError }`, validates `maxSize` / `allowedExtensions`), `injectDownloadFile(bucket, path, options?)` (`{ url, isLoading, error, refetch }`, refcounted shared object URL, OPFS-persisted by default, previous URL kept until the next is ready), `injectBlurhash(bucket, path, options?)`, `injectBucketImage(bucket, path, options?)` (adds `blurhash`, `ready` and `gate`). `bucket` and `path` may be signals. Name the schema for typed bucket names: `injectFileUpload<typeof schema>('avatars')`.
- **Components / directives** (standalone, import them in `imports`): `<sp00ky-bucket-image bucket path alt imgClass fit transition easing blurhash options>` (projected content = placeholder plate; host is the container), `<canvas [sp00kyBlurhash]="hash" [blurhashWidth] [blurhashHeight] [blurhashPunch]>` (`Blurhash`), `<img [sp00kyImageGate]="image">` (`ImageGate`; sets `src`, flips `image.ready()` on decode; do not bind `src` too).
- **`share(prev, next)`**, **`sameValue(a, b)`**: the pure helpers above, exported for tests and custom stores.

## Mutations

```ts
await this.db.create('post:' + crypto.randomUUID(), { title: 'Hi' });
await this.db.update('post', 'post:xyz', { title: 'Edited' });
await this.db.delete('post', row.id); // a row's RecordId works directly
await this.db.run('backend', 'sendMail', { to });
```

Track a backend job by querying its outbox row: `injectQuery(() => this.db.query('job_outbox').where({ id: this.jobId() }).one().build())`.

## Common gotchas

- **Queries need `.build()`** (or `.one().build()`). A bare `db.query('post')` is a builder.
- **Pass a function**, not a value, when the query depends on inputs or signals; `injectQuery(this.db.query('post').where({ id: this.id() }).build())` reads `id` once (and a required input throws NG0950 in a field initializer).
- **Call the signals**: `posts.data()`, not `posts.data`.
- **Injection context**: call `inject*` in field initializers or the constructor, not in `ngOnInit`, event handlers or after `await` (or pass `{ injector }`).
- **Field order**: declare `private readonly db = injectDb()` before the fields whose query functions use `this.db`.
- **No suspense / resource mode.** Branch on `isLoading()` / `isEmpty()`.
- **Angular CLI build settings** (worker entry, assets, prebundle) are required; see above.
- **SSR**: engine-backed components inside `@defer` or on `RenderMode.Client` routes.
- **`track post.id`** works: row ids are `RecordId` instances with stable identity per row under structural sharing.
