# `@spooky-sync/client-react`: agent guide

## What this package is

The **React** binding for sp00ky (React 18 and 19, peer `react`). Same `SyncedDb` and the same hook set as `@spooky-sync/client-solid` / `client-solid2`, written the React way: hooks return plain values, not accessors, and inputs are plain values (a query, an id, a path), not thunks.

Browser only (React DOM: Vite, Next.js client components, Remix). The core client runs SurrealDB / SQLite as WebAssembly with IndexedDB / OPFS and web workers, which React Native does not have. Do not suggest it for React Native; native mobile apps use the Flutter client.

Internals: every hook reads through `useSyncExternalStore` (tear-free, re-renders only when its value changed). `useQuery` feeds each live emission through a pure reducer (`reduceQuery` in `src/query.ts`) and structurally shares it with the previous result (`share`): rows matched by `id` keep their object identity, a deep-equal emission returns the same state and does not render. Client, registrations, CRDT fields, channels and file leases live in effects, so StrictMode's double mount ends with exactly one of each.

## Setup pattern

```ts
// db.ts
import type { SyncedDbConfig } from '@spooky-sync/client-react';
import { schema, SURQL_SCHEMA } from './schema.gen'; // generated by `spky generate`

export const dbConfig: SyncedDbConfig<typeof schema> = {
  schema,
  schemaSurql: SURQL_SCHEMA,
  database: {
    namespace: 'main',
    database: 'app',
    endpoint: 'ws://localhost:8666/rpc',
    store: 'indexeddb',
  },
};
```

```tsx
// App.tsx
<Sp00kyProvider config={dbConfig} fallback={<Splash />}>
  {/* app */}
</Sp00kyProvider>
```

Provider props: `config` (read once at mount; remount with a new `key` to switch databases), `fallback`, `preload` (awaited before children render, best-effort), `onReady`, `onError`. The client is created in an effect, so server renders show the fallback. A client that was handed to the tree is deliberately not closed on unmount; one whose init outlived the provider is.

Vite needs `vite-plugin-wasm`, `build.target: 'esnext'`, `optimizeDeps.exclude: ['@spooky-sync/client-react', '@spooky-sync/core', '@spooky-sync/ssp-wasm', '@surrealdb/wasm', '@surrealdb/wasm-native', '@sqlite.org/sqlite-wasm']` and `optimizeDeps.include: ['@spooky-sync/core > pino', '@spooky-sync/core > fast-json-patch']`. Pre-bundled, the client looks for its `.wasm` files and workers in the wrong folder (dev only: a 404 or `expected magic word`); `vite-plugin-top-level-await` is not needed and crashes with current `@swc/core`.

## Key API

- **`useDb<typeof schema>()`**: the `SyncedDb<S>`. `create`, `update`, `delete`, `query`, `preload`, `run`, `channel`, `bucket`, `remoteQuery`, `useRemote`, `auth` / `signOut`, `pendingMutationCount`, `syncHealth` / `storageHealth` and their subscribe methods. Throws outside a provider.
- **`useQuery(query, options?)`** (or `useQuery(db, query, options?)`): live query. `query` is a BUILT query (`.build()`, `.one().build()`), or `null` / `undefined` to skip. Build it inline: re-registration keys on the query's identity hash (surql + vars), not the object. Returns:
  - `data`: rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared between emissions.
  - `error`: registration / sync failure (e.g. SSP 503 NOT_READY). Never thrown; the scheduler retries.
  - `isLoading`: cold first load only (nothing painted for this identity, server not heard, no error). A cached paint ends it; the server answering with zero rows ends it.
  - `isFetching`: a fetch cycle is in flight.
  - `isAuthoritative`: `data` holds the rendered rows of a known membership (server's, or a previous session's on this device). Latched until the identity changes.
  - `hasData`: rows for a list, a row for `.one()`.
  - `isEmpty`: authoritative AND no data. Empty states go on this, never on `!hasData`.
  - `isSettled`: authoritative AND idle. Gate windowed-list end detection and create-if-missing on it. Not monotonic.
  - Options: `enabled?: boolean`, `deregisterOnCleanup?: boolean`.
  - On an identity change the previous `data` stays until the new identity emits (flags reset), so growing `.limit()` never flashes empty.
- **`usePreload(query, options?)`**: fire-and-forget prewarm of a likely-next query (`db.preload`), keyed on its identity. Options: `enabled?: boolean`, `signal?`.
- **`useSubmission(fn)`**: `{ submit, pending, error, result, clearError }`. `submit` is stable, calls the latest `fn`, never rejects. No optimistic layer: the engine already commits locally first.
- **`usePendingMutations()`**: number of unacknowledged local writes.
- **`useSyncStatus()`**: `{ health, status, isHealthy, isDegraded, everConnected, isOffline, connection, isReconnecting }`.
- **`useSyncActivity(options?)`** (or `(db, options?)`): `{ fetchingQueries, pendingMutations, isDownloading, isUploading }`, debounced on (`downloadDelayMs` 200, `uploadDelayMs` 150, `uploadThreshold` 0) and off at once.
- **`useStorageStatus()`**: `{ health, status, isPersistent, isMemoryFallback }`.
- **`useImpersonation({ rendersBanner? })`**: `{ impersonation, isImpersonating, stop }`.
- **`useFeatureFlag(key, { fallback?, ttl? })`**: `{ variant, payload, enabled }`.
- **`useAppRelease({ app, currentVersion, ttl? })`**: `{ latestVersion, updateAvailable, mandatory, cacheBust, reload }`.
- **`useCrdtField(table, recordId, field)`**: the `CrdtField` once loaded, else `null`. `recordId` is a value (`null` / `undefined` waits).
- **`useChannel(query, peers)`** (experimental): WebRTC channel while mounted for the rows `query` matches (a builder, built query, or list, on a `-- @channel` table; only its `where` counts; `null` closes it). Query and peers are compared by value. Returns `{ status, peers, update, create, delete }`. See `/docs/client/channels`.
- **Files**: `useFileUpload(bucket)` (`{ upload, download, remove, exists, isUploading, error, clearError }`, validates `maxSize` / `allowedExtensions`), `useDownloadFile(bucket, path, options?)` (`{ url, isLoading, error, refetch }`, refcounted shared object URL, OPFS-persisted by default), `useBlurhash(bucket, path)`, `useBucketImage(bucket, path, options?)` (adds `blurhash`, `ready`, and a `gate` ref callback for the `<img>`), components `<BucketImage bucket path className imgClassName fit fallback transition />` and `<Blurhash hash className style />`. Every file hook also takes `(db, bucket, ...)`.

## Mutations

```ts
await db.create('post:' + crypto.randomUUID(), { title: 'Hi' });
await db.update('post', 'post:xyz', { title: 'Edited' });
await db.delete('post', row.id); // a row's RecordId works directly
await db.run('backend', 'sendMail', { to });
```

Track a backend job by querying its outbox row: `useQuery(db.query('job_outbox').where({ id: jobId }).one().build())`.

## Common gotchas

- **Queries need `.build()`** (or `.one().build()`). A bare `db.query('post')` is a builder.
- **No Suspense mode.** There is no `ready()` like Solid 2; branch on `isLoading` / `isEmpty`.
- **`config` is read once.** Changing the provider's `config` prop does nothing; remount with a `key`.
- **React Native is unsupported** (no WebAssembly engines there).
- **Keys**: row ids are `RecordId` instances; use `key={String(row.id)}`.
- **Provider is mandatory** for every hook except the `(db, ...)` overloads.
