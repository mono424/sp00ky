`@spooky-sync/client-react` is the React binding. It wraps the same core client as the
[Solid bindings](/docs/guide/solid) and exposes the same hooks, written the React way: they return
plain values instead of accessors, and they re-render only when what they return changed. It works
with React 18 and 19.

<Warning title="React DOM, not React Native">
  The core client runs SurrealDB and SQLite as WebAssembly in the browser, with IndexedDB / OPFS
  storage and web workers. React Native's runtime has none of these, so this package targets React
  in the browser (Vite, Next.js client components, Remix, and so on). For a native mobile app use the
  [Flutter guide](/docs/guide/flutter).
</Warning>

## What "native" means here

- **Tear-free reads.** Every hook reads its state through `useSyncExternalStore`, so a concurrent
  render never sees two different versions of a query or of the sync status.
- **Structural sharing.** Each live emission is merged into the previous result: rows are matched
  by `id`, unchanged rows keep their object identity, and a deep-equal emission does not re-render
  at all. `React.memo` rows and `useMemo` deps keyed on a row only re-run when that row changed.
- **Lifecycle in effects.** The client, query registrations, CRDT fields, channels and file leases
  are opened in effects and released in their cleanups, never during render. StrictMode's double
  mount ends with exactly one of each.
- **No optimistic layer.** The engine already commits writes locally and re-renders through live
  queries before it syncs. Mutations are plain `await db.create(...)` calls; `useSubmission` only
  adds button pending and error state.

### Result surface

The flags are the same contract as the [Solid 2 binding](/docs/guide/solid2#result-surface), as
plain values:

| Field | Meaning |
|---|---|
| `data` | Rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared between emissions. |
| `error` | Registration or sync error (e.g. SSP 503 during bootstrap). Never thrown; the sync scheduler retries underneath. |
| `isLoading` | Cold first load only: nothing painted for this identity, the server has not answered, and registration has not failed. A paint from the local cache ends it; the server answering with zero rows ends it too. |
| `isFetching` | The sync engine is pulling records for this query (registration, a sync round). |
| `isAuthoritative` | `data` holds the rendered rows of a known membership: the server's answer, or the one a previous session left on this device. From here `data` is an answer, not a cache guess. |
| `hasData` | `data` holds something: rows for a list, a row for `.one()`. |
| `isEmpty` | Authoritative **and** no data: the server said "no rows". Render empty states on this, never on a bare `!hasData`. |
| `isSettled` | Authoritative **and** idle. The gate for trusting a short window as the end of a list, and for "create it if it is missing". Not monotonic: a later sync round re-enters `isFetching`. |

When the query's identity changes, the previous `data` stays on screen until the new identity
emits, while the flags reset. Growing a `.limit()` therefore never flashes an empty list:

## Coming from the Solid bindings

| client-solid / client-solid2 | client-react |
|---|---|
| `useQuery(() => q)` / `createQuery(() => q)` | `useQuery(q)`, with `null` to skip |
| `posts.data()`, `posts.isLoading()` | `posts.data`, `posts.isLoading` |
| `{ enabled: () => boolean }` | `{ enabled: boolean }` |
| `ready()` + `<Loading>` | not available yet: branch on `isLoading` |
| `createSubmission(fn)` | `useSubmission(fn)` |
| `createPreload(() => q)` | `usePreload(q)` |
| `useCrdtField(table, () => id, field)` | `useCrdtField(table, id, field)` |
| `useDownloadFile(bucket, () => path)` | `useDownloadFile(bucket, path)` |
| `<BucketImage class="...">` | `<BucketImage className="...">` |
| everything on `useDb()` | unchanged |

<Note title="Next.js">
  The bundle starts with `'use client'`, so a server component (an App Router layout) can render
  `<Sp00kyProvider>` directly. The provider renders its `fallback` on the server; data loads in the
  browser, from the local cache first.
</Note>

export const providerCode = `import { Sp00kyProvider } from '@spooky-sync/client-react';
import { dbConfig } from './db';
import { MainContent } from './MainContent';

export default function App() {
  return (
    <Sp00kyProvider
      config={dbConfig}
      fallback={<div>Initializing database…</div>}
      preload={async (db) => {
        // Optional: warm the local cache before the UI is revealed.
        await db.preload(db.query('config').build());
      }}
      onError={(err) => console.error('Failed to initialize database:', err)}
    >
      <MainContent />
    </Sp00kyProvider>
  );
}`;

export const queryCode = `import { useDb, useQuery } from '@spooky-sync/client-react';
import type { schema } from '../schema.gen';

export function PostList() {
  const db = useDb<typeof schema>();
  const posts = useQuery(
    db.query('post').related('author').orderBy('created_at', 'desc').limit(20).build()
  );

  if (posts.isLoading) return <div>Loading…</div>;
  if (posts.isEmpty) return <div>No posts yet.</div>;
  return (
    <ul>
      {posts.data.map((post) => (
        <li key={String(post.id)}>
          {post.title} by {post.author?.username}
        </li>
      ))}
    </ul>
  );
}`;

export const submissionCode = `import { useSubmission } from '@spooky-sync/client-react';

function NewPost() {
  const db = useDb<typeof schema>();
  const [title, setTitle] = useState('');
  const save = useSubmission((t: string) => db.create('post:' + crypto.randomUUID(), { title: t }));

  return (
    <form onSubmit={(e) => { e.preventDefault(); void save.submit(title); }}>
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <button disabled={save.pending}>Save</button>
      {save.error && <p>{save.error.message}</p>}
    </form>
  );
}`;

export const statusCode = `import { useSyncStatus, usePendingMutations } from '@spooky-sync/client-react';

function ConnectionBanner() {
  const sync = useSyncStatus();
  const pending = usePendingMutations();
  if (!sync.isDegraded) return null;
  return <Banner>Can't reach the server, {pending} change(s) queued.</Banner>;
}`;

export const filesCode = `import { BucketImage, useFileUpload } from '@spooky-sync/client-react';

function Avatar({ path }: { path: string | null }) {
  return <BucketImage bucket="avatars" path={path} className="h-12 w-12 rounded-full" alt="" />;
}

function AvatarUpload() {
  const { upload, isUploading, error } = useFileUpload('avatars');
  return (
    <input
      type="file"
      disabled={isUploading}
      onChange={(e) => {
        const file = e.target.files?.[0];

      }}
    />
  );
}`;
