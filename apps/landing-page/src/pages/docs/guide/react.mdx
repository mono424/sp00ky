`@spooky-sync/client-react` brings Sp00ky to React 18 and 19. Your components read live queries
through hooks that return plain values, every write lands in the local database first, and the
engine keeps that database in sync with the server and with every other tab and device in the
background. Queries paint from the local cache on reload, keep working offline, and update the
moment anyone changes a row they match.

This guide walks through a complete app: setup, queries, sign-in, writes, sync status, files,
collaborative fields and peer to peer channels.

<Warning title="React DOM, not React Native">
  The client runs SurrealDB and SQLite as WebAssembly in the browser, with IndexedDB / OPFS storage
  and web workers. React Native's runtime has none of these, so this package targets React in the
  browser (Vite, Next.js client components, Remix, and so on). For a native mobile app use the
  [Flutter guide](/docs/guide/flutter).
</Warning>

## How it fits React

- **Tear-free reads.** Every hook reads its state through `useSyncExternalStore`, so a concurrent
  render never sees two different versions of a query or of the sync status.
- **Structural sharing.** Each live update is merged into the previous result: rows are matched by
  `id`, unchanged rows keep their object identity, and an update that changed nothing does not
  re-render at all. `React.memo` rows and `useMemo` deps keyed on a row only re-run when that row
  changed.
- **Lifecycle in effects.** The client, query registrations, CRDT fields, channels and file leases
  are opened in effects and released in their cleanups, never during render. StrictMode's double
  mount ends with exactly one of each.
- **Local-first writes.** The engine commits a write locally and re-renders every affected query
  before it syncs, so there is no optimistic layer to maintain. Mutations are plain
  `await db.create(...)` calls; `useSubmission` adds button pending and error state.

### Result

`useQuery` returns plain values, recomputed only when they change:

| Field | Meaning |
|---|---|
| `data` | Rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared between updates. |
| `error` | Registration or sync error (e.g. SSP 503 during bootstrap). Never thrown; the sync scheduler retries underneath. |
| `isLoading` | Cold first load only: nothing painted for this query, the server has not answered, and registration has not failed. A paint from the local cache ends it; the server answering with zero rows ends it too. |
| `isFetching` | The sync engine is pulling records for this query (registration, a sync round). |
| `isAuthoritative` | `data` holds the rendered rows of a known membership: the server's answer, or the one a previous session left on this device. From here `data` is an answer, not a cache guess. |
| `hasData` | `data` holds something: rows for a list, a row for `.one()`. |
| `isEmpty` | Authoritative **and** no data: the server said "no rows". Render empty states on this, never on a bare `!hasData`. |
| `isSettled` | Authoritative **and** idle. The gate for trusting a short window as the end of a list, and for "create it if it is missing". Not monotonic: a later sync round re-enters `isFetching`. |

When the query's identity changes, the previous `data` stays on screen until the new query
answers, while the flags reset. Growing a `.limit()` therefore never flashes an empty list:

viewport windows that mount and unmount a query per page, see [Pagination](/docs/client/pagination).

## Sync status

`useSyncStatus` reports the connection, `usePendingMutations` the number of writes not yet on the

|---|---|
| `useSyncStatus()` | `status`, `isHealthy`, `isDegraded`, `isOffline`, `isReconnecting`, `everConnected`, `connection`, `health` |
| `usePendingMutations()` | The number of local writes waiting to sync |
| `useSyncActivity(options?)` | `isDownloading`, `isUploading`, `fetchingQueries`, `pendingMutations`, debounced for a traffic indicator |

## Next.js and server rendering

The bundle starts with `'use client'`, so a server component (an App Router layout) can render
`<Sp00kyProvider>` directly. The provider renders its `fallback` on the server; data loads in the
browser, from the local cache first. Keep components that call the hooks below the provider and
inside client components.

export const authCode = `import { useEffect, useState } from 'react';
import { useDb } from '@spooky-sync/client-react';
import type { schema } from '../schema.gen';

export function useAuth() {
  const db = useDb<typeof schema>();
  // undefined until the client reports, then a user id or null.
  const [userId, setUserId] = useState<string | null | undefined>(undefined);

  // subscribe() answers right away with the current user, then on every
  // sign-in and sign-out. It returns the unsubscribe the effect cleans up with.
  useEffect(() => db.auth.subscribe(setUserId), [db]);

  return {
    userId,
    isChecking: userId === undefined,
    signIn: (username: string, password: string) =>
      db.auth.signIn('account', { username, password }),
    signUp: (username: string, password: string) =>
      db.auth.signUp('account', { username, password }),
    signOut: () => db.signOut(),
  };
}`;

export const signInCode = `import { useState } from 'react';
import { useSubmission } from '@spooky-sync/client-react';
import { useAuth } from '../lib/auth';

export function SignIn() {
  const auth = useAuth();
  const [username, setUsername] = useState('');
  const [password, setPassword] = useState('');
  const signIn = useSubmission(auth.signIn);

  if (auth.isChecking) return null;
  if (auth.userId) return <button onClick={auth.signOut}>Sign out</button>;

  return (
    <form onSubmit={(e) => { e.preventDefault(); void signIn.submit(username, password); }}>
      <input value={username} onChange={(e) => setUsername(e.target.value)} />
      <input type="password" value={password} onChange={(e) => setPassword(e.target.value)} />
      <button disabled={signIn.pending}>Sign in</button>
      {signIn.error && <p>{signIn.error.message}</p>}
    </form>
  );
}`;

export const crdtCode = `import { useEffect, useState } from 'react';
import { useCrdtField } from '@spooky-sync/client-react';

// id is the full record id, e.g. 'note:abc'; summary is the column's plain text.
function Summary({ id, summary }: { id: string; summary: string }) {
  const field = useCrdtField('note', id, 'summary');
  const [value, setValue] = useState(summary);

  // Follow the document: local and remote edits alike re-render the input.
  useEffect(() => {
    const doc = field?.getDoc();
    if (!doc) return;
    const text = doc.getText('summary');
    setValue(text.toString());
    return doc.subscribe(() => setValue(text.toString()));
  }, [field]);

  return (
    <textarea
      value={value}
      readOnly={!field}
      onChange={(e) => {
        const doc = field?.getDoc();
        if (!doc) return;
        doc.getText('summary').update(e.target.value); // minimal diff
        doc.commit();
      }}
    />
  );
}`;
