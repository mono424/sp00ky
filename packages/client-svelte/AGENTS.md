# `@spooky-sync/client-svelte`: agent guide

## What this package is

The **Svelte 5** binding for sp00ky, built on runes (peer `svelte@^5.29.0`; Svelte 4 is not supported). Same `SyncedDb` and the same hook set as `@spooky-sync/client-react` / `client-solid2`, written the Svelte way:

- A hook returns an object whose fields are **reactive getters**: `posts.data`, `posts.isLoading`. Read them in markup, `$derived` or `$effect`. **Never destructure** a result: `const { data } = useQuery(...)` is a one-time copy.
- An input that should follow state is a **getter**: `useQuery(() => db.query('post').where({ author: id }).build())`, `useCrdtField('post', () => postId, 'body')`, `useDownloadFile('covers', () => path)`. A plain value is read once.
- A hook with a single value returns `{ current }` (the `svelte/reactivity` convention): `usePendingMutations().current`, `useCrdtField(...).current`.

Browser only. The core client runs SurrealDB / SQLite as WebAssembly with IndexedDB / OPFS and web workers, and does not load on the server. In SvelteKit set `export const ssr = false` in the root `+layout.ts`.

Internals: `useQuery` keeps rows in `$state.raw` and structurally shares each live emission with the previous one (`share` in `src/query.svelte.ts`): rows matched by `id` keep their object identity, a deep-equal emission is the same value, rows are plain objects (never deep proxies). Status hooks are built on `createSubscriber` (subscribed only while read, reading the engine's own current value). Registrations, CRDT fields, channels and file leases live in `$effect` and end with the component. `SyncedDb` writes copy plain objects / arrays (`plain()`) so a `$state` proxy never reaches the workers, leaving `RecordId` / `Date` / bytes untouched (`$state.snapshot` would turn a RecordId into a string via `toJSON`).

The package ships Svelte source built by `svelte-package` (`.svelte`, `.svelte.js`, `.d.ts`; `svelte` export condition), compiled by the app's own compiler.

## Setup pattern

```ts
// src/lib/db.ts
import type { SyncedDbConfig } from '@spooky-sync/client-svelte';
import { schema, SURQL_SCHEMA } from './schema.gen'; // generated by `spky generate`

export const dbConfig: SyncedDbConfig<typeof schema> = {
  schema,
  schemaSurql: SURQL_SCHEMA,
  database: {
    namespace: 'main',
    database: 'app',
    endpoint: 'ws://localhost:8666/rpc',
    store: 'indexeddb',
  },
};
```

```svelte
<!-- src/routes/+layout.svelte -->
<script lang="ts">
  import { Sp00kyProvider } from '@spooky-sync/client-svelte';
  import { dbConfig } from '$lib/db';
  let { children } = $props();
</script>

<Sp00kyProvider config={dbConfig}>
  {#snippet fallback()}<Splash />{/snippet}
  {@render children()}
</Sp00kyProvider>
```

Provider props: `config` (read once at mount; wrap in `{#key}` to switch databases), `fallback` (snippet), `preload` (awaited before children render, best-effort), `onReady`, `onError`, `children`. The client is created in `onMount`, so server renders show the fallback. A client that was handed to the tree is deliberately not closed on destroy; one whose init outlived the provider is.

Without the provider: create `new SyncedDb(config)`, `await db.init()` (e.g. in a SvelteKit `load`), and call `setDbContext(db)` while the root layout initialises.

Vite needs `vite-plugin-wasm`, `build.target: 'esnext'`, `optimizeDeps.exclude: ['@spooky-sync/client-svelte', '@spooky-sync/core', '@spooky-sync/ssp-wasm', '@surrealdb/wasm', '@surrealdb/wasm-native', '@sqlite.org/sqlite-wasm']` and `optimizeDeps.include: ['@spooky-sync/core > pino', '@spooky-sync/core > fast-json-patch']`. Pre-bundled, the client looks for its `.wasm` files and workers in the wrong folder (dev only: a 404 or `expected magic word`); `vite-plugin-top-level-await` is not needed and crashes with current `@swc/core`.

## Key API

Hooks that read context (`useDb`, and every hook without an explicit `db`) or open something must run while a component initialises (top level of `<script>`), or inside `$effect.root` with an explicit `db`.

- **`useDb<typeof schema>()`**: the `SyncedDb<S>`. `create`, `update`, `delete`, `query`, `preload`, `run`, `channel`, `bucket`, `remoteQuery`, `useRemote`, `auth` / `signOut`, `pendingMutationCount`, `syncHealth` / `storageHealth` and their subscribe methods. Throws outside a provider.
- **`useQuery(query, options?)`** (or `useQuery(db, query, options?)`): live query. `query` is a getter returning a BUILT query (`.build()`, `.one().build()`) or `null` / `undefined` to skip; a fixed built query can be passed directly. Re-registration keys on the identity hash (surql + vars), not on rebuilds. Result getters:
  - `data`: rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared.
  - `error`: registration / sync failure (e.g. SSP 503 NOT_READY). Never thrown; the scheduler retries.
  - `isLoading`: cold first load only (nothing painted for this identity, server not heard, no error).
  - `isFetching`: a fetch cycle is in flight.
  - `isAuthoritative`: `data` holds the rendered rows of a known membership. Latched until the identity changes.
  - `hasData`: rows for a list, a row for `.one()`.
  - `isEmpty`: authoritative AND no data. Empty states go on this, never on `!hasData`.
  - `isSettled`: authoritative AND idle. Gate windowed-list end detection and create-if-missing on it. Not monotonic.
  - Options: `enabled?: boolean | (() => boolean)`, `deregisterOnCleanup?: boolean`.
  - On an identity change the previous `data` stays until the new identity emits (flags reset), so growing `.limit()` never flashes empty.
- **`usePreload(query, options?)`** (or `(db, query, options?)`): fire-and-forget prewarm of a likely-next query, keyed on its identity. Options: `enabled?`, `signal?`.
- **`useSubmission(fn)`**: `{ submit, pending, error, result, clearError }`. `submit` never rejects. Needs no component or provider.
- **`usePendingMutations(db?)`**: `{ current: number }`.
- **`useSyncStatus(db?)`**: `{ health, status, isHealthy, isDegraded, everConnected, isOffline, connection, isReconnecting }`. With an explicit `db` it works in a shared `.svelte.ts` module.
- **`useSyncActivity(options?)`** (or `(db, options?)`): `{ fetchingQueries, pendingMutations, isDownloading, isUploading }`, debounced on (`downloadDelayMs` 200, `uploadDelayMs` 150, `uploadThreshold` 0), off at once. Owns timers: component init or `$effect.root`.
- **`useStorageStatus(db?)`**: `{ health, status, isPersistent, isMemoryFallback }`.
- **`useImpersonation({ rendersBanner? }, db?)`**: `{ impersonation, isImpersonating, stop }`.
- **`useFeatureFlag(key, { fallback?, ttl? }, db?)`**: `{ variant, payload, enabled }`. The handle closes with the component.
- **`useAppRelease({ app, currentVersion, ttl? }, db?)`**: `{ latestVersion, updateAvailable, mandatory, cacheBust, reload }`.
- **`useCrdtField(table, recordId, field, db?)`**: `{ current: CrdtField | null }`, `null` until loaded. `recordId` is a getter (or value).
- **`useChannel(query, peers, db?)`** (experimental): WebRTC channel for the component's lifetime for the rows `query` matches (a builder, built query, or list, on a `-- @channel` table; only its `where` counts; `null` closes it). Both arguments may be getters, compared by value. Returns `{ status, peers, update, create, delete }`. See `/docs/client/channels`.
- **Files**: `useFileUpload(bucket)` (`{ upload, download, remove, exists, isUploading, error, clearError }`, validates `maxSize` / `allowedExtensions`), `useDownloadFile(bucket, path, options?)` (`{ url, isLoading, error, refetch }`, refcounted shared object URL, OPFS-persisted by default, previous URL kept until the next is ready), `useBlurhash(bucket, path)`, `useBucketImage(bucket, path, options?)` (adds `blurhash`, `ready`, and `gate`, an attachment: `<img {@attach image.gate} alt="" />` that sets `src` itself; do not also bind `src`). Every file hook also takes `(db, bucket, ...)`; `path` is a getter or value.
- **Components**: `<BucketImage bucket path class imgClass fit transition easing blurhash options>` with an optional `fallback` snippet; `<Blurhash hash width height punch class style />`.
- **`setDbContext(db)`**: provide a self-created client to the tree instead of rendering `<Sp00kyProvider>`.
- **`plain(value)`**, **`share(prev, next)`**, **`sameValue(a, b)`**: the pure helpers above, exported for tests and custom stores.

## Mutations

```ts
await db.create('post:' + crypto.randomUUID(), { title: 'Hi' });
await db.update('post', 'post:xyz', { title: 'Edited' });
await db.delete('post', row.id); // a row's RecordId works directly
await db.run('backend', 'sendMail', { to });

let draft = $state({ title: '' });
await db.create('post:' + crypto.randomUUID(), draft); // proxies are copied, fine
```

Track a backend job by querying its outbox row: `useQuery(() => db.query('job_outbox').where({ id: jobId }).one().build())`.

## Common gotchas

- **Queries need `.build()`** (or `.one().build()`). A bare `db.query('post')` is a builder.
- **Pass a getter**, not a value, when the query depends on props or state; `useQuery(db.query('post').where({ id }).build())` captures `id` once.
- **Do not destructure** results; read `result.field`.
- **Call hooks during component init**, not in event handlers or after `await`.
- **No suspense mode.** There is no `ready()` like Solid 2; branch on `isLoading` / `isEmpty`.
- **`config` is read once.** Changing the provider's `config` does nothing; remount it with `{#key}`.
- **SvelteKit SSR must be off** for routes that render the provider (`export const ssr = false`).
- **Keys**: row ids are `RecordId` instances; use `{#each rows as row (String(row.id))}`.
