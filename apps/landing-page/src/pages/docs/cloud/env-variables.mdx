Sp00ky Cloud provides encrypted environment variable storage that syncs across your team. Each variable supports separate **development** and **production** values, so your local dev setup and production deployment stay in sync without `.env` files.

All values are encrypted at rest using the tenant's [Shared Vault](/docs/reference/vault). For details on the encryption model, key hierarchy, and security properties, see the vault documentation.

<Note title="Infrastructure knobs are not vault variables">
The SSP, scheduler and SurrealDB containers take their environment from the control plane, with
<code>deployment.env</code> in <code>sp00ky.yml</code> as the per-role override. A few of those are
derived from <code>sp00ky.yml</code> for you: <code>SPKY_INGEST_TRANSPORT</code> and
<code>SPKY_CHANGEFEED_RETENTION</code> from <code>sync.transport</code>, and
<code>SPKY_SSP_QUERY_ALLOWLIST</code> from <code>sync.queryAllowlist</code>. See
<a href="/docs/cloud/deploying#infrastructure-environment-variables">Deploying</a>.
</Note>

## Initializing the Vault

Before using environment variables, initialize your encryption vault:

<CodeBlock
  code={code29}
  lang="bash"
/>

You'll be prompted to:
1. **Choose a vault passphrase**: this protects your encryption keys, so pick something strong
2. **Confirm the passphrase**
3. **Optionally cache the derived key** locally in `~/.sp00ky/vault-derived-key` (the raw passphrase is never written to disk; only its Argon2id-derived key)

If you skip `env unlock`, the vault will be created automatically the first time you run `env set`.

<Note title="Teams">
The first team member to run <code>env unlock</code> creates the tenant vault. Other members receive vault access through the invitation flow. They set their own passphrase when accepting the invitation. See <a href="/docs/reference/vault">Shared Vault</a> for details.
</Note>

## Setting Variables

<CodeBlock
  code={code28}
  lang="bash"
/>

The CLI will interactively ask you:

1. **Variable name** (if not provided as argument)
2. **Which environment(s)**: choose from:
   - *Both (same value)*: use one value for dev and prod
   - *Development only*
   - *Production only*
   - *Both (different values)*: prompts for each separately
3. **The value**: entered with masked input (like a password prompt)

Variable names are automatically uppercased. Running `env set` on an existing variable updates only the environments you specify. It won't overwrite the other environment's value.
