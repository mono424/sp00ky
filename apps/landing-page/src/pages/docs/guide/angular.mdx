`@spooky-sync/client-angular` connects Angular apps to Sp00ky, built on signals. A live query is an
object of read-only signals (`posts.data()`, `posts.isLoading()`) that templates, `computed()` and
`effect()` track like any other signal. Every write lands in the local database first, and the
engine syncs it with the server and every other tab and device in the background. Reloads paint
from the local cache, and the app keeps working offline.

This guide builds a complete app: setup, queries, sign-in, writes, sync status, files,
collaborative fields and peer to peer channels. It needs Angular 21 or newer, and works with
zoneless and zone.js apps alike.

<Warning title="Browser only">
  The client runs SurrealDB and SQLite as WebAssembly with IndexedDB / OPFS storage and web
  workers, so it only runs in the browser. During a server render `provideSp00ky` never starts it;
  render the components that use it on the client, as shown in
  [Server-side rendering](#server-side-rendering).
</Warning>

## Queries

`injectQuery(query, options?)` subscribes a component to a live query. It takes a function that
builds the query: the function re-runs when the signals it reads change, and the query is
re-registered only when its identity (its SurrealQL and vars) changes, not on every rebuild. Like
every `inject*` function it runs in an injection context (a field initializer or the constructor)
and ends with it; pass `{ injector }` to call it anywhere else.

A query that never changes can be passed as is (`injectQuery(this.db.query('tag').build())`). The
query builder itself (`where`, `related`, `orderBy`, `limit`, `one`) is covered in
[Reactive queries](/docs/client/queries).

<Note title="Call the field, keep the object">
  Every field is a signal: read it as `posts.data()` in templates, `computed()` and `effect()`.
  Keep the result object on the component and call fields where you need them; a field read once
  in the constructor is a one-time copy.
</Note>

### Result

Every field of the result is a read-only signal:

| Field | Meaning |
|---|---|
| `data` | Rows, or the row / `null` for `.one()`. `[]` / `null` before the first result. Structurally shared between updates: unchanged rows keep their object identity, and an update that changes nothing does not notify. |
| `error` | Registration or sync error (e.g. SSP 503 during bootstrap). Never thrown; the sync scheduler retries underneath. |
| `isLoading` | Cold first load only: nothing painted for this query, the server has not answered, and registration has not failed. A paint from the local cache ends it; the server answering with zero rows ends it too. |
| `isFetching` | The sync engine is pulling records for this query (registration, a sync round). |
| `isAuthoritative` | `data` holds the rendered rows of a known membership: the server's answer, or the one a previous session left on this device. From here `data` is an answer, not a cache guess. |
| `hasData` | `data` holds something: rows for a list, a row for `.one()`. |
| `isEmpty` | Authoritative **and** no data: the server said "no rows". Render empty states on this, never on a bare `!hasData()`. |
| `isSettled` | Authoritative **and** idle. The gate for trusting a short window as the end of a list, and for "create it if it is missing". Not monotonic: a later sync round re-enters `isFetching`. |

When the query's identity changes, the previous `data` stays on screen until the new query
answers, while the flags reset. Growing a `.limit()` therefore never flashes an empty list:

<CodeBlock code={loadMoreCode} lang="typescript" />

Options: `{ enabled?: boolean | Signal<boolean>, deregisterOnCleanup?: boolean, injector?: Injector }`.
Use `deregisterOnCleanup` for viewport windows that mount and unmount a query per page, see
[Pagination](/docs/client/pagination).

## Sync status

`injectSyncStatus` reports the connection, `injectPendingMutations` the number of writes not yet on

| Function | Returns |
|---|---|
| `injectSyncStatus()` | `status`, `isHealthy`, `isDegraded`, `isOffline`, `isReconnecting`, `everConnected`, `connection`, `health` |
| `injectPendingMutations()` | a signal: the number of local writes waiting to sync |
| `injectSyncActivity(options?)` | `isDownloading`, `isUploading`, `fetchingQueries`, `pendingMutations`, debounced for a traffic indicator |

## Files and images

[`injectFileUpload` and `injectDownloadFile`](/docs/client/buckets) upload to and read from a
bucket. `<sp00ky-bucket-image>` renders a bucket file as an image, revealing it only once it is
decoded, with the stored blurhash as a placeholder while it loads. Paths (and bucket names) may be
signals. On a path change the previous object URL stays valid until the next one is ready, so the

import type { schema } from './schema.gen';

@Injectable({ providedIn: 'root' })
export class Auth {
  private readonly db = injectDb<typeof schema>();

  /** undefined until the client reports, then a user id or null. */
  readonly userId = signal<string | null | undefined>(undefined);

  constructor() {
    // subscribe() answers right away with the current user, then on every

    inject(DestroyRef).onDestroy(this.db.auth.subscribe((id) => this.userId.set(id)));
  }

  signIn(username: string, password: string) {
    return this.db.auth.signIn('account', { username, password });
  }

  signUp(username: string, password: string) {
    return this.db.auth.signUp('account', { username, password });
  }

  signOut() {
    return this.db.signOut();
  }
}`;

export const crdtTsCode = `import { ChangeDetectionStrategy, Component, effect, input, signal } from '@angular/core';
import { injectCrdtField } from '@spooky-sync/client-angular';

@Component({
  selector: 'app-note-summary',
  templateUrl: './note-summary.html',
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class NoteSummary {
  /** The full record id, e.g. 'note:abc'. */
  readonly id = input.required<string>();
  /** The column's plain text, shown until the document has loaded. */
  readonly summary = input.required<string>();

  protected readonly field = injectCrdtField('note', this.id, 'summary');
  protected readonly value = signal('');

  constructor() {
    // Follow the document: local and remote edits alike update the textarea.
    effect((onCleanup) => {
      const doc = this.field()?.getDoc();
      if (!doc) return;
      const text = doc.getText('summary');
      this.value.set(text.toString());
      onCleanup(doc.subscribe(() => this.value.set(text.toString())));
    });
  }

  protected edit(event: Event): void {
    const doc = this.field()?.getDoc();
    if (!doc) return;
    doc.getText('summary').update((event.target as HTMLTextAreaElement).value); // minimal diff
    doc.commit();
  }
}`;

export const crdtHtmlCode = `<textarea
  [value]="field() ? value() : summary()"
  [readOnly]="!field()"
  (input)="edit($event)"
></textarea>`;
